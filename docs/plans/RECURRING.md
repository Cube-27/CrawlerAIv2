# Recurring findings

Mistakes that agents made more than once, and what now prevents each one. The orchestrator keeps this file
current (`/run-plan` §2a). A finding that recurs gets a **check** where one can catch it (lint rule, `tools/` scan, CI
step); a **skill rule** only where no check can. Workers read this list before opening a PR (`/implement-pr` §4).

| Finding | Seen in | Prevented by |
|---|---|---|
| A CLI path argument is read without a base-directory check (SonarCloud `pythonsecurity:S8707`, path traversal). | #21, #22, #30 | Skill rule (`/implement-pr` §4): resolve the path and refuse it outside the working directory or repo root, with a test, as `fetch --out` does (D-0146). |
| A `pytest.raises` block holds more than one statement or call (SonarCloud `python:S5778`). | #20, #23, #30, #33 | Check: ruff `PT012` (one statement). Skill rule for nested calls, which `PT012` doesn't see: build arguments before the `with`. |
| A worker reports DONE while the PR's SonarCloud gate is red. | #28, #30 | Skill rule (`/implement-pr` §6): DONE requires the PR's gate `OK`. `tools/orchestrator/wait_ci.sh` prints the gate. |
| Duplicated lines on new code push the SonarCloud gate over 3%. | #28 | Watch. Skill rule if it recurs. |
| Throwaway test Postgres containers, their anonymous volumes and Docker build cache outlive their worktree (21.8 GB of cache and 2 leaked volumes by 2026-10-13). | #28, #30, owner | `tools/orchestrator/cleanup_worktree.sh` on merge removes `crawlerai-*` containers with `-v`, removes all build cache (owner: no cache needed) and drops dangling images; skill rule (`/implement-pr` §3): remove containers with `-v` and images you build. |
| A herdr pane starts in the home folder because the cwd string was built inline (`"...\$wt"` drops the variable). | orchestrator, twice | `tools/orchestrator/start_agent.sh` builds the path and checks the agent's cwd. |
| An orchestrator tracker commit written early conflicts with a PR that merged first. | #26 | Superseded: the tracker commit is written only on `YOUR TURN`, one PR at a time (`/run-plan` §1.3). |
| A wait loop reads the previous commit's CI results. | orchestrator | `tools/orchestrator/wait_ci.sh` waits on the head SHA. |
| A merge ran after a failed CI wait (`wait_ci.sh ... ; gh pr merge`), so #38's last commit merged before its CI ran. Main stayed green. | orchestrator (#38) | `tools/orchestrator/merge_pr.sh`: merges only on a passing wait, pinned to the head commit; `wait_ci.sh` tolerates the old head right after a push and exits 1 on a failed check. |
| Sonar shell rules on orchestrator scripts (`shelldre`: `[[`, errors to stderr, `case` default, explicit `return`). | #40 | Watch. Skill rule if it recurs. |
| A prompt sent while the agent was still loading was dropped, and `start_agent.sh` reported the agent idle. | orchestrator (SPEC-02 PR 6 worker) | `start_agent.sh` waits 15 s for a turn, resends once, then fails and closes the pane. |
| Agent panes split the orchestrator's pane downward, stacking into rows one or two lines high that the owner can't read. | orchestrator (owner) | `start_agent.sh` opens each agent in its own tab labelled with its name. |
| Idle reviewer panes stayed open after their verdict, about 400 MB each, and caused low-memory reaping. It recurred after the self-close rule; one reviewer concluded it was not in a herdr pane although `$HERDR_PANE_ID` was set. | orchestrator (owner), #97, #99 | Skill rule (`/review-pr` §4): the reviewer closes its own pane first (`herdr pane close "$HERDR_PANE_ID"`). Skill rule (`/implement-pr` §6): when the verdict arrives, the implementor closes the reviewer by name with `tools/orchestrator/close_agent.sh reviewer-pr<n>`. |
| A worker stopped to ask the orchestrator to "resume" or "proceed", or merged its own PR when asked in its pane; #71 merged without its tracker commit. | #71, orchestrator | Skill rule (`/implement-pr` §6): keep going until `READY`; never merge your own PR unless the owner explicitly overrides. `merge_pr.sh` is the orchestrator's merge path. |
| The watcher woke on a transient `unknown` agent status: herdr reports it briefly for agents still working (`SETTLED <name> unknown`, three false wake-ups on 2026-10-13). | orchestrator | Check: `tools/orchestrator/watch_agents.sh` treats `unknown` as working. |
| An agent tab opened in another project's herdr workspace: `herdr tab create` without `--workspace` uses the focused one (impl-s05p7 and reviewer-pr87, 2026-10-13). | orchestrator | `tools/orchestrator/start_agent.sh` passes `--workspace "$HERDR_WORKSPACE_ID"` and fails when it is unset. |
| The orchestrator started `watch_agents.sh` detached with `&` instead of as a tracked background task, so that watcher could never notify it (2026-10-13). | orchestrator, twice | Check: `tools/orchestrator/watch_agents.sh` is single-instance (pidfile in the git common dir; exits 2 while a live watcher holds it). Skill rule (`/run-plan` §1a): start it only as a tracked background task, never with `&`. |
| An implementor merged its own PR, skipping `merge_pr.sh` and the tracker commit; #100 acted on a message in its pane. | #71, #100 | Check: a PreToolUse hook in `.claude/settings.json` runs `tools/orchestrator/merge_guard.py` on every Bash and PowerShell call and denies `gh pr merge`, the REST merge endpoint and the GraphQL merge mutations; `tools/orchestrator/merge_pr.sh` is the only path that passes. |
| `wait_ci.sh` waited about 30 minutes for checks on a PR that conflicted with main: GitHub starts no `pull_request` workflow on a conflicting PR, so only CodeRabbit and SonarCloud reported. | #109 | Check: `tools/orchestrator/wait_ci.sh` (and `merge_pr.sh`, which calls it) exits 1 at once when the PR is `CONFLICTING`/`DIRTY` (`rebase onto origin/main`), and when no workflow run exists for the head after 5 minutes. |
